# Windows 설치 및 smoke 결과

공개용 기록의 SSH 별칭·세션 이름·사용자 경로는 가상 예시로 바꿨다.
`windows-pc`는 실제 접속 대상이 아니다. 아래 결과는 2026-09-06 관찰이며 이번 정리에서 재실행하지 않았다.

2026-09-06, Mac CLI에서 기존 `windows-pc` SSH 연결로 Windows 데스크톱을 검증했다.
기본 조회와 접근성 조작은 통과했다. 일반 키 입력과 포커스 복구에는 실패 사례가 남아 있다.

## 설치 상태

- Windows 설치: `%USERPROFILE%\.windows-use\app`, 버전 `0.1.0`.
- Node.js `v24.19.0`, Windows PowerShell `5.1.26100.9168`.
- SSH 프로세스는 세션 0, `serve`는 로그인된 사용자 데스크톱 세션 1에서 실행한다.
- 수동 데스크톱 시작 작업: `Interactive`, `Limited`, 자동 트리거 없음.
- 작업 스케줄러는 세션 1에서 서버를 시작하는 데만 사용했다. 자동 로그인 실행,
  장애 재시작, 안정적인 `start/status/stop` 명령은 아직 구현하지 않았다.
- 설치 패키지는 45,237바이트, 런타임 파일 18개이며 파일별 SHA-256을 대조했다.
- 패키지 SHA-256: `b57c7f44ceff2d0e862858a7c7a39d5dcf5b5ec99fb5445173ef0b6cd3de6ca9`.

## 검증

| 범위 | 결과와 근거 |
| --- | --- |
| Mac 로컬 테스트 | 14/14 통과 |
| Windows 설치본 테스트 | 14/14 통과, 실제 Windows named pipe 사용 |
| 원본 PowerShell 렌더링 테스트 | `windows-snapshot-render-tests-ok` |
| 포커스 helper smoke | 잘못된 인증 거절, 다른 창 소유자 거절, 인증된 종료 통과 |
| Mac → SSH → Windows named pipe | `capabilities`, `apps`, `windows` 통과 |
| 실제 Windows 관찰 | 테스트 창 접근성 트리와 창 범위 스크린샷 확인 |
| `set-value` | 한글, 이모지, 줄바꿈, 따옴표, `$`가 UIA 값과 테스트 창 기록에서 일치 |
| 접근성 `click` | `Invoke`로 버튼 실행, 화면 `Applied: 1`과 클릭 횟수 1 확인 |
| 한글 `type-text` | 수정 전 `keyboard smoke \\?=B`, 수정 후 `keyboard smoke 한글🙂`로 일치 |
| 일반 키 입력 | ASCII `!` 입력이 반영되지 않음. 후속 `abc` 시도는 `window_not_focused`로 거절됨 |
| 정리 | 접근성 버튼으로 WPF 창 종료, `closed: true` 확인. 테스트 프로세스·임시 작업·원격 테스트 상태 삭제 |

키보드 명령의 `verification.state`는 `unverified`이므로 성공 응답만으로 통과 처리하지 않았다.
한글 입력은 별도 관찰과 테스트 창의 실제 문자열을 대조했다.
전체 Orca 내장 `orca computer` 연동, 로그인/재부팅 후 복구, 잠금 화면,
관리자 권한 앱, 다른 Windows 앱의 호환성은 검증하지 않았다.

## 수정 사항

1. `src/broker.mjs`: Windows named pipe에서 쓰기 방향 종료 후 응답이 비는 문제를
   재현했다. 요청과 응답을 줄바꿈 JSON으로 구분하고 응답을 받을 때까지 연결을 유지한다.
   수정 전 Windows IPC 테스트 2개와 추가 회귀 테스트가 실패했고, 수정 후 통과했다.
2. `native/computer-use-windows/runtime.ps1`: P/Invoke를 `PostMessageW`에 명시적으로
   연결해 한글 및 UTF-16 surrogate pair의 ANSI 변환을 막았다.
   `test/windows-keyboard-smoke.mjs`로 실제 Windows에서 실패→통과를 확인했다.
   `provenance.json`의 `localModifications`에 변경 이유와 현재 해시를 기록했다.

## 남은 보완

- 창 포커스와 입력칸 포커스를 각각 진단하고, 일반 키 입력 결과를 검증해야 한다.
  `--restore-window`만으로 입력칸까지 선택되는 것은 아니다. 지원되는 입력칸에서는
  `set-value`를 우선 사용한다.
- 수동 작업 종료 시 서버 자식 프로세스와 등록 파일의 정리가 즉시 확인되지 않았다.
  이번 교체에서는 이 작업에서 만든 서버만 식별해 종료하고, 종료 확인 후 등록 파일을 삭제했다.
- 초기 WinForms 테스트 창은 UIA 패턴을 노출하지 않았다. 입력·버튼 검증은 WPF 창에서 수행했다.
- F4 조합은 현재 런타임에서 지원하지 않는다. 테스트 창은 접근성 닫기 버튼으로 정리했다.

## 사용 및 증거

Mac의 일반 에이전트 셸에서 실행:

```sh
windows-use apps --host windows-pc
windows-use snapshot --host windows-pc --app <PID> --session <작업-ID>
```

서버가 중단됐다면 기존 프로세스와 등록 파일을 확인한 뒤 해당 환경의 시작 절차를 따른다.
수동 작업 이름과 재시작 절차는 이식 가능한 설치 계약이 아니므로 공개 예시에서 생략한다.
등록 파일의 인증 정보는 출력하거나 공유하지 않는다.
